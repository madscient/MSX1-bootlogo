# 技術仕様

MSX1 起動ロゴ ROM の仕様・設計・検証状況をまとめた、開発者向けの資料です。使い方とビルドの手順は [README](../README.md) にあります。

この資料のうち、ROM 自身の動作（何をどこに書くか、どの順で処理するか）は、ソースコードと検証プログラムで確かめられる内容です。MSX 本体・BIOS・特定の機種の挙動についての記述は、エミュレータ（openMSX）で確かめたものと、確かめていないものがあります。実機では確かめていません。確認の状況は「[検証状況](#検証状況)」にまとめています。

## バイナリ仕様

- Z80、MSX1 の Graphics II（SCREEN 2）、256×192、VRAM 16KB。
- サイズは 16,384 バイト。4000h–7FFFh に配置。マッパー不要。コードとデータのあとは FFh で埋めます。
- ヘッダ: `41 42 10 40 00 00 00 00 00 00 00 00 00 00 00 00`。INIT は 4010h。STATEMENT / DEVICE / TEXT はすべて 0。
- メイン BIOS が page 0、RAM が page 3 にある標準の MSX 起動環境を前提にします。
- INIT は BIOS から渡されたスタックをそのまま使い、RET で BIOS の ROM 検索へ戻ります。常駐フックや強制リセットは使いません。
- 画面の初期化は BIOS の CHGMOD で行います。アニメーションの間は割り込みを許可し、BIOS のフレームカウンタ（JIFFY）を時間の基準にします。

## 画面

| 領域 | VRAM |
|---|---|
| パターン | 0000h–17FFh |
| 名前 | 1800h–1AFFh |
| 色 | 2000h–37FFh |

- ロゴは x=47–212、y=53–101。黒い矩形は x=32–223、y=48–111。
- RAM 容量の表示は x=64、y=120 から 15 文字（8 ドット幅）。
- 色テーブルは F1h（白/黒）で始め、上から 8 走査線ずつ F4h（白/青）に変えます。ロゴ周囲の矩形は F1h のまま残します。最後に画面外のボーダーも R7=04h（dark blue）にします。
- レーザーはスプライトではなくパターンに描きます。スプライトの横 4 枚制限を受けません。

## 作業 RAM

C000h–D89Fh を使います。D8A0h 以上には書き込みません。呼び出し元である BIOS のスタックは page 3 の高位側（F0xxh 付近、機種によってはそれより低い）にあるので、作業領域をそこから離しています。

| アドレス | 用途 |
|---|---|
| C000h–D7FFh | 表示中のパターン画像（レーザーを含む）。6,144 バイト |
| D800h | 各段階の進行カウンタ |
| D803h | レーザーの描画（1）／消去（0） |
| D804h | 100ms あたりのフレーム数（60Hz: 6、50Hz: 5） |
| D805h | 次の締切（JIFFY の下位バイト） |
| D806h–D807h | 次に読むシナリオのアドレス |
| D808h–D809h | 直前に描いたシナリオのアドレス（消去用） |
| D80Ah | 50Hz 用の端数の繰り越し |
| D80Bh | 更新間隔の選択（0: 50ms、1: 100ms） |
| D810h–D814h | 描画中のレーザー 1 本（x、y、dx、dy、長さ） |
| D820h–D821h | ミラー経由の 2 回目の呼び出しを見分ける目印（5Ah、A5h） |
| D822h | 自カートリッジのスロット ID |
| D823h | 主 RAM のスロット ID |
| D824h | 検出した RAM 容量（KB） |
| D825h | ミラーの有無 |
| D826h–D827h | フォントのアドレス |
| D840h–D843h | 検査地点の元データ |
| D844h–D847h | ページごとの検査結果 |
| D880h–D89Fh | タイル列ごとの「輪郭が出現済み」フラグ（32 列） |

INIT の最後に C000h–D89Fh をすべて 0 に戻してから RET します。ミラーがある場合だけ、目印の 2 バイトを残します。ミラー経由の 2 回目の呼び出しは、目印を消してすぐに戻りますが、その前に書いた D822h（自スロットの ID）は消さないので、この 1 バイトが残ります。

## 時間の管理

- BIOS 002Bh の bit 7 で 50Hz / 60Hz を判定します。
- 更新の基本単位は 50ms です。60Hz では 3 フレーム、50Hz では 2 フレームと 3 フレームを交互に使って平均 50ms にします。
- レーザーの区間だけは 100ms 単位（60Hz で 6 フレーム、50Hz で 5 フレーム）で、36 段階です。
- 各段階は「前の締切＋間隔」まで HALT で待つ方式なので、描画にかかった時間は間隔に含まれます。
- ロゴの完成までが 114 段階で 7.5 秒、RAM 容量の表示が 40 段階で 2 秒です。RAM 容量の検査と文字の描画を終えてから締切を取り直すので、検査にかかる時間は 2 秒に含まれません。
- NTSC の厳密な走査周波数などにより、実時間にはわずかな差が出ます。

## レーザーと輪郭の描画

- シナリオは 1 段階ごとに、輪郭を出現させるタイル列（なければなし）と、レーザー 3 本ぶんの線分を持ちます。
- 輪郭と塗りつぶしは、ROM 内の画像からタイル列（8 ドット幅 × 画面の高さ）単位で RAM の画像と VRAM へ写します。輪郭は列 4–27 を決まった順で、塗りつぶしは列 4 から 27 へ順に写します。
- レーザーは RAM の画像に重ねて描き、次の段階の前に消します。消すときは、その列の輪郭が出現済みなら ROM の輪郭画像のバイトを、未出現なら 0 を書き戻します。輪郭の完成形を RAM に別途持つことはしません。

## VDP への書き込み

パターンと色の 1 バイト書き込みは、アドレス 2 バイトとデータ 1 バイトの全体を DI / EI で囲みます。途中で割り込みが入ると、BIOS の割り込み処理がステータスを読んで VDP のアドレスラッチを戻してしまうためです。

## 8000h ミラーへの対応

16KB の ROM は、エミュレータの設定や単純なカートリッジ基板によっては 8000h–BFFFh にも同じ内容が見えます。BIOS の ROM 検索は各スロットの 4000h と 8000h の両方で AB 署名を調べるので、ミラーがあると INIT が 2 回呼ばれます。

- INIT の先頭で自スロット（RSLREG と EXPTBL / SLTTBL から求める）の 8000h と 8001h を RDSLT で読み、ミラーの有無を判定します。
- ミラーがある場合だけ、1 回目の終了時に D820h / D821h へ目印を書きます。2 回目の呼び出しでは目印を消して、すぐに RET します。
- ミラーがない場合は目印を残さないので、リセットのたびに必ず再生されます。

この仕組みは「ミラーがあれば BIOS は INIT を 2 回呼ぶ」ことを前提にしています。純正 BIOS の機種（openMSX 上の Sony HB-10、HB-11、National CF-2000、Canon V-20）は 2 回呼びます。ミラーがあっても INIT を 1 回しか呼ばない BIOS では、目印が消されずに RAM に残ります。リセットで RAM の内容が保たれると、次の起動の INIT が目印を見てすぐに戻るので、アニメーションは再生されません。その次の起動では再生されます。openMSX 21.0 の C-BIOS 0.29（MSX1）がこれに当たります。C-BIOS の MSX2 機種はリセット時に RAM を初期化するので、毎回再生されます。

## RAM 容量の検査

page 3 に選択されている主 RAM のスロットについて、16KB のページ 4 つを調べます。

- 主スロットは RSLREG、拡張の有無は EXPTBL から求めます。
- 副スロットは、page 3 から見える FFFFh（副スロットレジスタの反転値）を直接読んで求めます。BIOS が持つ副スロットレジスタの写し（SLTTBL）は使いません。写しが page 3 の実際の選択と合っていない環境では別の副スロットを指してしまい、その状態で RDSLT / WRSLT を呼ぶと BIOS が page 3 を切り替えて、スタックと作業領域のある RAM が見えなくなるためです。
- 0100h / 4100h / 8100h / C100h に、ページごとに異なる検査値を 2 回書いて読み戻します。page 0–2 は RDSLT / WRSLT、page 3 は直接読み書きします（page 3 にスロット間呼び出しを使わない理由は上と同じです）。
- ページごとに値を変えるので、ミラーされたページは 1 回しか数えません。2 回とも合ったページだけを RAM とするので、ROM や空き領域は数えません。
- 検査の前に 4 地点の元データを保存し、検査のあとに戻します。検査中は割り込みを禁止します。
- RAMAD0–3 は使いません。ディスクのない MSX1 では設定されている保証がないためです。

## RAM 容量の文字表示

`Main RAM : ##KB` は本体のシステムフォントで表示します。文字列は ROM 内に ASCII で持ち、各文字の 8×8 パターンをフォントから SCREEN 2 のパターンテーブルへ LDIRVM で転送します。

フォントの場所は、CGPNT（F91Fh–F921h）がメイン ROM のスロットを指していればそのアドレス、そうでなければメイン ROM の 0004h（CGTABL）が指すアドレスです。

## 終了処理と BASIC への復帰

RAM 容量を 2 秒表示したあと、SCREEN 1（前景 15、背景と周辺 4）に戻し、作業 RAM を消去して RET します。BIOS の ROM 検索がそのまま続き、そのあと BASIC が起動します。

## 内蔵ソフトを持つ機種

Sony HB-11 は、カートリッジがなくても BASIC ではなく内蔵ソフトが起動する機種です。この ROM を挿した場合も、アニメーションのあとに内蔵ソフトが起動します。openMSX 21.0 の HB-11（主 RAM は副スロット 3-2）で、RAM 容量が 64KB と表示されること、INIT から戻ったあと画面が SCREEN 2 になり、page 1 に内蔵ソフトのスロット 3-0 が選択されていることを確認しています。カートリッジなしで起動した場合も同じ状態になります。

以下は**未検証**です。根拠となる測定の記録はリポジトリになく、確かめていません。

- 内蔵ソフトが起動する仕組み: 内蔵ファームウェアが INIT で H.STKE に「スロット 3-0 の 5E60h を呼ぶ」フックを設定する（スロット番号 83h が固定で書かれている）。
- ファームウェアを 3-1、RAM を 3-0 に置いたエミュレータのマシン定義では、フックが RAM の 5E60h に飛ぶ。この場合の動作は ROM 側では回避できない。

## アセット

`assets/` の 3 ファイルは `tools/gen_assets.py` の出力で、手で編集するものではありません。ROM の内容が Python の疑似乱数の実装に左右されないように、生成結果をリポジトリに入れています。

| ファイル | 形式 |
|---|---|
| `outline.dat`、`solid.dat` | SCREEN 2 のパターンテーブルと同じ並びの 6,144 バイト。点 (x, y) は、オフセット (y÷8)×256 + (x÷8)×8 + (y mod 8) のバイトの、bit 7 を左端とするビット |
| `beams.dat` | 16 バイトのレコードが 36 個。先頭 1 バイトが輪郭を出現させるタイル列（255 はなし）、続いて 5 バイト（x、y、dx、dy、長さ）の線分が 3 本。dx と dy は符号付き、長さ 0 は線分なし |

- ロゴは多角形の頂点列として持ち、480×424 の座標を 256×192 に縮小して塗りつぶします。輪郭は、塗りつぶしのうち上下左右のどれかが外側である点です。
- レーザーの向きと始点、輪郭の出現順は、固定シードの疑似乱数から決めます。

```text
python tools/gen_assets.py          3 ファイルを書き出す
python tools/gen_assets.py --check  書き出さずに比較し、違いがあれば終了コード 1
```

標準ライブラリだけで動きます。Python の疑似乱数の実装に依存するので、別のバージョンの Python で同じ結果になるかは `--check` で確かめてください（確認済みなのは Python 3.13.14 だけです）。

## ビルド

`python tools/build.py` でビルドします。使い方は [README](../README.md#ビルド) にあります。

- スクリプトは、リポジトリのルートでアセンブラを実行し、できたイメージ（4000h から `rom_end` まで）の後ろを FFh で埋めて 16,384 バイトにします。イメージの大きさが `rom_end` と合わないとき、16KB を超えるときは、エラーで止まります。
- 埋め草をソースに書かないのは、zmac が `ds` の埋め値に 128 以上を受け付けないためです。
- ソースは zmac、sjasmplus、Pasmo の 3 つが受け付ける構文だけで書いています。
- `incbin` のパスはリポジトリのルートからの相対パスです。3 つとも追加のオプションなしで解決できる書き方にしています。
- アセンブラごとに形式の違うシンボルの一覧を読み、`build/symbols.json`（ラベル名とアドレス）にまとめます。2 つの検証スクリプトはこのファイルを読みます。

出力（`build/` 以下）: `msx_logo.rom`、`symbols.json`、アセンブラの出力（`msx_logo.cim` は埋める前のイメージ。`msx_logo.lst`、`msx_logo.sym` はアセンブラによってある場合とない場合があります）。

## 検証プログラム

2 つあります。`tools/verify.py` は BIOS を持たない小さな模擬環境で、細かい構成を数多く試せます。`tools/test_openmsx.py` は openMSX の上で、本物の BIOS 実装（C-BIOS）と一緒に動かします。

### 模擬環境での検証

`tools/verify.py` は、ビルドした ROM の Z80 命令を実行し、BIOS の呼び出しを代わりに処理する検証用のプログラムです。MSX 全体のエミュレータではありません。検査に 1 つでも通らなければ、エラーで止まります。

検査する内容:

- ROM のサイズ、AB 署名、INIT のアドレス、コードとデータが 8000h に収まること。
- 50Hz と 60Hz のそれぞれで全体を実行し、段階の数（154）、各段階が締切どおりであること、ロゴ完成までの時間、RAM 容量の表示が 2 秒であること。
- 輪郭が完成した時点のパターンが `outline.dat` と一致すること、最終のパターンが `solid.dat` と RAM 容量の文字に一致すること。
- 色テーブルの最終状態、青い領域が上から 1 段ずつ増えること、黒い矩形が保たれること、R7 が 04h であること。
- VRAM への直接書き込みが、パターンと色のテーブルの範囲に収まること。名前テーブルが標準の並びのままで、スプライトが無効になっていること。
- RAM 16 / 32 / 48 / 64KB、主スロット／拡張スロット、16 / 32KB ミラーの構成で、容量が正しいこと、検査地点の元データが戻ること、page 3 に RDSLT / WRSLT を使わないこと。
- 8000h にミラーがある場合に、1 回目は再生して目印を残し、2 回目はすぐに戻って目印を消すこと。ミラーがない場合は目印を残さないこと。
- 終了時に作業 RAM が 0 に戻っていること、D8A0h–F2FFh が書き換えられていないこと、スタックポインタと呼び出し元のスタックの内容が保たれていること。

限界:

- 実装している Z80 命令と BIOS 呼び出しは、この ROM が使うものだけです。それ以外に出会うとエラーで止まります。
- BIOS は代替処理で、純正 BIOS のコードは実行しません。フォントも代用です。
- 命令の実行時間は数えますが、割り込み処理の時間、M1 ウェイト、VDP の競合は再現しません。
- 検査するのは実行した結果です。実行時に参照されない ROM のバイトが変わっても検出しません。ビルド結果が同じかどうかは SHA-256 で比べてください。

出力（`build/` 以下）: `verification.json`。Pillow がある場合は加えて `preview.gif`、`final.png`、`frame_*.png`、`storyboard.png`。GIF は RAM 容量の表示までの 9.5 秒を繰り返す形で、BASIC の画面は含みません。

### openMSX での検証

`tools/test_openmsx.py` は、ビルドした ROM をカートリッジとして openMSX を起動し、ブレークポイントで機械の状態を記録して（`tools/openmsx_test.tcl`）、その記録を検査します。openMSX は環境変数 `OPENMSX_DIR` のフォルダから、なければ PATH から探します。

- ウィンドウを開かず、最高速で実行します。9 通りの構成で 10 秒ほどです。
- openMSX のユーザーデータのフォルダを `build/openmsx/` に切り替えて起動するので、利用者自身の openMSX の設定は読み書きしません。
- RAM の配置を変えた機種は、openMSX に付属する C-BIOS の機種定義から派生させて `build/openmsx/` に作ります。

試す構成:

| 構成 | 機種 |
|---|---|
| 60Hz、ROM ミラーあり | C-BIOS_MSX1 |
| 50Hz、ROM ミラーあり | C-BIOS_MSX1_EU |
| ROM ミラーなし（`Normal4000`）、リセット 1 回 | C-BIOS_MSX1 |
| ROM ミラーあり、リセット 1 回 | C-BIOS_MSX1 |
| RAM 64KB を副スロット 3-2 に置く | C-BIOS_MSX1 から派生 |
| RAM 48KB を副スロット 3-2 に置く | C-BIOS_MSX1 から派生 |
| RAM 16KB を副スロット 3-1 に置く | C-BIOS_MSX1 から派生 |
| RAM 32KB をスロット 3 に置く | C-BIOS_MSX1 から派生 |
| RAM 16KB をスロット 3 に置く | C-BIOS_MSX1 から派生 |

起動のたびに検査する内容:

- INIT が呼ばれ、呼び出し元へ戻ること。戻ったときにスタックの内容が保たれていること。D8A0h からスタックの手前までが書き換えられていないこと。
- アニメーションがちょうど 1 回再生されること（段階の数が 154）。
- ロゴ完成までの時間と、RAM 容量を表示している時間が、フレーム数で合っていること。
- 自スロットの判定、ミラーの判定、主 RAM のスロットの判定、RAM 容量が、ROM を通さずに openMSX から読んだ値と一致すること。
- RAM の検査地点の内容が、検査の前後で同じであること。
- 最終画面のパターンが `solid.dat` と、BIOS のフォントで描いた RAM 容量の文字に一致すること。色、名前テーブル、スプライトの終端、R7。
- 終了時に作業 RAM が目印を除いて 0 であること。
- INIT から戻って 6 秒後に、CPU がカートリッジの外を実行していること。

`--machine 機種名` を付けると、上の 9 通りの代わりに openMSX のその機種で 1 回（リセット 1 回つき）試します。純正 BIOS の機種を試すにはそのシステム ROM が必要です。openMSX 本体の `share/systemroms` に加えて、環境変数 `MSX_ROM_DIRS` に並べたフォルダ（PATH と同じ区切り）から探します。ROM は SHA-1 で照合されるので、openMSX の機種定義が求めるものと同じ内容のファイルでなければ見つかりません。

検査のうち「INIT から戻って 6 秒後」の画面の文字は、合否には使わず結果に記録します。純正 BIOS の機種では、ここに BASIC の起動メッセージと `Ok` が記録されます。

限界:

- 既定の構成はすべて C-BIOS です。C-BIOS には BASIC がないので、BASIC のプロンプトまで確かめるには `--machine` で純正 BIOS の機種を指定します。
- エミュレータ上の確認であり、実機の確認ではありません。
- 「スタックの手前まで」は、INIT に入った時点のスタックポインタの 256 バイト下までです。

- **確認済み** — 実際に実行して確かめた。
- **不合格** — 実際に実行して、意図どおりでないことを確かめた。
- **未検証** — 記述はあるが、確かめた記録がリポジトリになく、確かめていない。
