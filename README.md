# MSX1 起動ロゴアニメーション

MSX1 用の 16KB カートリッジ ROM です。リセットするとロゴのアニメーションとメイン RAM の容量を表示し、そのあとは通常どおり BASIC が起動します。

![アニメーションのプレビュー](docs/images/preview.gif)

プレビューは検証用プログラムが描いた画面を画像にしたもので、エミュレータの録画ではありません。RAM 容量の文字は代用フォントで描いてあり、実際には本体のフォントで表示されます。プレビューは繰り返し再生されますが、ROM は 1 回再生して BASIC へ進みます。

## 使い方

1. 下の「ビルド」の手順で `build/msx_logo.rom` を作ります。
2. エミュレータのカートリッジスロットに挿入し、MSX1 としてリセットします。

ROM タイプを手動で指定する場合は、4000h 開始の標準 16KB ROM（Normal ROM、マッパーなし）を選びます。BLOAD 用のヘッダ付きファイルではありません。

## 動作

| 開始から | 演出 |
|---|---|
| 0–0.5 秒 | 黒背景 |
| 0.5–4.1 秒 | 最大 3 本のレーザーが縦・横・斜めに飛び交い、各所に輪郭が現れる |
| 4.1–4.3 秒 | 完成した白い輪郭を表示 |
| 4.3–5.5 秒 | 左から右へ輪郭の内部を白く塗りつぶす |
| 5.5–6.7 秒 | ロゴの黒い矩形を残して、外側の背景を上から下へ青く塗る |
| 6.7–7.5 秒 | 完成画面を表示 |
| 約 7.5 秒 | メイン RAM の容量を検査し、ロゴの下に `Main RAM : ##KB` と表示 |
| 続く 2 秒 | ロゴと RAM 容量の表示を保持 |
| 約 9.5 秒 | BIOS の起動処理へ戻り、通常どおり BASIC へ進む |

- 時間はカートリッジの画面初期化が終わってからの目安です。本体 BIOS 自身の起動表示や待ち時間は含みません。
- 50Hz 機と 60Hz 機のどちらでも同じ長さで再生します。
- 音はありません。
- レーザーの動きは毎回同じです。
- 青は MSX1 の固定パレットの色 4 です。MSX2 の起動画面の青とは色味が異なります。
- ロゴは MSX2 の起動画面を参考に輪郭を描き起こしたもので、ピクセル単位の再現ではありません。
- 他のカートリッジや起動ディスクによる自動起動は、本体 BIOS の本来の動作に従います。

## RAM 容量の表示

標準的な MSX1 の 16 / 32 / 48 / 64KB を対象に、メイン RAM として選択されているスロットの RAM 容量を表示します。BASIC の空きメモリ量ではありません。

次のものは数えません。

- 8KB 以下の MSX
- 64KB を超えるメモリマッパーの総容量（たとえば 128KB のマッパーでも、その時点で見えている 64KB を超える分は数えません）
- 複数のスロットに分かれた増設 RAM の合計
- 16KB 未満の単位でミラーされる特殊な構成

## 既知の制限

- 実機では動作を確認していません。エミュレータ（openMSX）では、C-BIOS の機種と純正 BIOS の機種で確認しています。確認できている範囲は [技術仕様の「検証状況」](docs/technical.md#検証状況) にあります。
- C-BIOS の MSX1 機種で、ROM が 8000h 以降にもミラーされる設定（openMSX が 16KB の ROM に自動で選ぶ設定）のときは、リセットのたびに「再生する」「再生しない」が交互になります。ROM タイプをミラーなし（openMSX では `Normal4000`）にすると、リセットのたびに再生します。
- HB-11 のように内蔵ソフトを持つ機種では、アニメーションのあと BASIC ではなく内蔵ソフトが起動します。これはその機種の本来の起動動作です。

## ビルド

Python 3 と、次の Z80 アセンブラのどれか 1 つが必要です。3 つとも同一の ROM ができることを確認しています。

- [zmac](http://48k.ca/zmac.html) 18oct2022
- [sjasmplus](https://github.com/z00m128/sjasmplus) 1.24.0
- [Pasmo](https://pasmo.speccy.org/) 0.5.4.beta2

```text
python tools/build.py
```

`build/msx_logo.rom`（16,384 バイト）が ROM です。

アセンブラは、次の環境変数に実行ファイルのパスが入っていればそれを使い、なければ PATH から探します。上から順に探して、最初に見つかったものを使います。`--asm zmac` のように指定すると、そのアセンブラだけを使います。

| アセンブラ | 環境変数 | PATH で探す名前 |
|---|---|---|
| zmac | `ZMAC_EXE` | `zmac` |
| sjasmplus | `SJASMPLUS_EXE` | `sjasmplus` |
| Pasmo | `PASMO_EXE` | `pasmo` |

ビルドスクリプトがするのは、リポジトリのルートでアセンブラを実行することと、できたイメージの後ろを FFh で埋めて 16KB にすることです。ほかのアセンブラでは確認していません。ソースが使っているのは、`0x` 形式の 16 進数、`org`、`db`、`dw`、`ds`、`incbin`、行頭のコロン付きラベルだけです。

## 検証

ビルドした ROM を確かめるスクリプトが 2 つあります（Python 3.13 で確認）。どちらも、検査に 1 つでも通らなければ 0 以外の終了コードで終わります。

```text
python tools/verify.py
python tools/test_openmsx.py
```

`tools/verify.py` は、ROM の Z80 命令を実行し、BIOS の呼び出しを代わりに処理する限定的な検証用プログラムです。MSX 全体のエミュレータではありません。結果は `build/verification.json` に書き出します。[Pillow](https://python-pillow.org/) が入っていれば、プレビュー画像（`build/preview.gif` など）も書き出します。

`tools/test_openmsx.py` は、[openMSX](https://openmsx.org/) で ROM を実際に起動して確かめます。openMSX は、環境変数 `OPENMSX_DIR`（openMSX の実行ファイルがあるフォルダ）から、なければ PATH から探します。ウィンドウは開かず、openMSX の設定も変更しません。結果は `build/openmsx_test.json` に書き出します。現在の ROM では、上の「既知の制限」にある C-BIOS でのリセットの検査 1 件が不合格になります。

`python tools/test_openmsx.py --machine Sony_HB-10` のように openMSX の機種名を付けると、その機種で試します。純正 BIOS の機種にはそのシステム ROM が必要で、openMSX 本体の `share/systemroms` と、環境変数 `MSX_ROM_DIRS` に並べたフォルダ（PATH と同じ区切り）から探します。
